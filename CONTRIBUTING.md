# Contributing

Issues and pull requests are welcome. Contributions are accepted under the [Apache License 2.0](LICENSE), the
licence of the project (section 5 of the licence).

## Ground rules

1. **Every number has a source.** A physical parameter is a datasheet value (put the URL in the catalog entry), a
   measurement (say how it was measured), or a derivation written next to it (`tools/`, `docs/notes/`). No tuning
   constants that only make a test pass. Where an effect is missing, say so in the entry's limitations or in
   [ROADMAP.md](ROADMAP.md).
2. **Sensors look like the real driver.** A simulated sensor publishes the topics, message types, frame_ids,
   rates and QoS of the real product's ROS 2 driver, so code written against the simulation runs on hardware.
3. **ROS conventions.** SI units and axes per REP-103, `map -> odom -> base_link` per REP-105, IMU topics per
   REP-145, launch arguments with descriptions (`ros2 launch <pkg> <file> --show-args`).
4. **When Gazebo cannot model an effect, write a plugin** (see `fleet_gz_plugins`, `fleet_marine_plugins`,
   `fleet_aircraft`) rather than fudging a parameter.

## Common changes

| change | guide |
|---|---|
| add a sensor, motor, battery or other part | [components README](src/fleet_components/components/README.md), [swap a sensor](docs/guides/swap_a_sensor.md) |
| add a robot | [add a robot](docs/guides/add_a_robot.md) |
| add a world | [add a world](docs/guides/add_a_world.md) |
| change the AUV | [AUV guide](docs/guides/auv.md) |
| change the drone or add a PX4 airframe | [aircraft guide](docs/guides/aircraft.md) |

Meshes and SDF are generated by the Blender scripts in `blender/` and committed. Change the script, re-run it
(commands in the [README](README.md#regenerating-assets-with-blender)), and commit both the script and its output.

## Before opening a pull request

```bash
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install && source install/setup.bash
scripts/run_all_tests.sh --quick          # about 2 min of test time on a built workspace
```

If the change touches navigation, physics or a robot's drive, also run the matching rows: `scripts/run_all_tests.sh --list`
shows the row names, `--only REGEX` runs a subset. A known failure (XFAIL) that starts passing is good news: remove it
from `XFAIL_WHY` in `scripts/run_all_tests.sh` and from [ROADMAP.md](ROADMAP.md).

Keep pull requests to one topic and describe how you checked the result (test rows, plots, measurements).
