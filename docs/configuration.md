## Robot config (robots.yaml)

File: `src/fleet_description/config/robots.yaml`. One top-level key per robot; it is the single source for
xacro (`src/fleet_description/urdf/robot.urdf.xacro`), `blender/build_robots.py` and the bringup launch. The
header comments in the file are the full key reference; the essentials:

| key | applies to | meaning |
|---|---|---|
| `label` | all | display name |
| `kind` | legged only | `legged`; absent means wheeled |
| `components` | all | catalog entries by file stem, per role (below) |
| `battery_pack {series, parallel}` | all | cells of the catalog `battery_cell` in the pack |
| `mounts` | all | base_link position (m) of pack and driver(s); layout choices, the CoM follows |
| `wheel_radius`, `wheel_width`, `wheel_separation`, `wheel_x`, `left_wheels`, `right_wheels`, `casters` | wheeled | drive geometry (m); `wheel_x` is each axle's x |
| `wheel_separation_multiplier` | wheeled | diff-drive odometry factor; 1.0 for round/box. Rover and truck still carry a measured skid-steer factor (see README, G5) |
| `leg_type`, `knee`, `standing_height`, `crouch_height`, `link`, `joint`, `limits`, `legs`, `gait` | legged | leg kinematics, joint effort/velocity limits, gait; semantics in the file header and `fleet_legged/kinematics.py` |
| `body` | all | Blender style parameters, collision primitives, `foot_mu` (legged) |
| `lidar`, `imu`, `camera` | all | x, y, z (m) of the sensor above the floor (`camera` also `pitch`) |
| `footprint`, `robot_radius` | all | Nav2 footprint polygon (m, base_footprint) and radius |
| `max_vel_x`, `max_vel_y`, `max_vel_theta`, `height` | all | Nav2 speed limits (m/s, rad/s) and body height |

Component roles: `lidar` (category `lidar`), `imu` (`imu`), `camera` (`depth_camera`), `wheel_motor` (`dc_motor`),
`motor_driver`, `battery_cell` (`battery`), `tyre`, `joint_actuators {coxa, femur, tibia}` (`servo`). Changing a
name changes the URDF, the driver emulator parameters and, after `tools/mass_properties.py`, the mass budget.

Do not put mass, CoM or inertia in robots.yaml: they are outputs (next section).

Other kinds keep their own configs:
- AUV: `src/fleet_auv/config/knucker.yaml` (layout, component stems) and `knucker_physics.yaml` (exported from
  `tools/derive.py`; derived values in `knucker_derived.json`). `model.py` generates the SDF and URDF.
- Wyvern: `blender/drone/make_sdf.py` reads the catalog and writes `src/fleet_drone/models/wyvern/model.sdf`.

## Mass properties

`src/fleet_description/config/mass_properties.yaml` is generated by `python3 tools/mass_properties.py`
from robots.yaml, `structure_materials.yaml` (material densities), the catalog (part masses and sizes) and
`blender/robots/part_stats/*.json` (volumes and inertia integrated from the Blender meshes). Parallel-axis
sums give total mass, CoM and inertia about the CoM per link. Do not edit it; a test (`test_mass_properties_current`)
fails when it is stale. Not budgeted: SBC, wiring, fasteners, PCBs, battery holder.

## Component catalog schema

Directory `src/fleet_components/components/<category>/<vendor>_<model>.yaml` (schema and rules in that
directory's README.md). Keys:

| key | content |
|---|---|
| `model`, `category`, `vendor` | product identity; category equals the directory |
| `datasheet`, `sources` | primary URL and every other source with what it was used for |
| `specs` | datasheet values in SI, the original units kept in comments |
| `ros_driver` | the real driver the simulation reproduces: `package`, `topics` (type per relative name), `frame_id`, `rate_hz`, `qos` |
| `sim` | how specs map to Gazebo or plugin parameters, derivation next to each value |
| `limitations` | what is not reproduced |

Rules: every `specs` number has a source; values the vendor does not publish are marked `unpublished` with the
estimate and how it was obtained; no factor chosen to make a test pass. Xacro macros in
`src/fleet_components/urdf/<category>.xacro` load the entry with `xacro.load_yaml` (see `urdf/README.md`).
Driver emulators (`fleet_sensor_sim`, `fleet_auv/sensor_drivers.py`) read the same entries for noise,
covariances, rate and topic names.

## Worlds

Per world, in `src/fleet_worlds/`:

| file | content |
|---|---|
| `worlds/<w>.sdf` | the Gazebo world: physics (DART with dantzig, `<engine>` in the Physics system), `CoulombFriction` plugin, sensors systems, models |
| `worlds/<w>.yaml` | `spawn {x, y, yaw}`; `spawns` (named poses); `map`; `goals` (name, x, y, yaw, zone, used by Nav2 tests); `short_pairs`; `drone` (takeoff, cruise_altitude, waypoints); `auv` (keep only) |
| `maps/<w>.{pgm,yaml}` | occupancy grid for AMCL, generated by `tools/make_map.py` |
| `models/<w>_env/` | meshes, collision and `model.sdf` |

Generated by `blender -b --factory-startup -P blender/build_worlds.py -- --world <w>`. Sources of floor
friction pairs and physics settings are in the SDF comments and `docs/notes/ground.md` (G2). A new world needs a
generator module in `blender/` following the existing ones, a `<w>.yaml` with `spawn` and `goals`, a map, and
`colcon build --packages-select fleet_worlds` (wrap in the worlds lock when other agents work). The checks
`python3 tools/check_world.py <w>` and `scripts/run_all_tests.sh --only world_check` validate it.

Named spawn: `ros2 launch fleet_bringup sim.launch.py robot:=hound world:=lab spawn:=workshop`; `x:= y:= yaw:=`
override the pose (m, rad, world frame, ENU).

## Launch arguments

Always up to date: `ros2 launch <pkg> <file> --show-args`. `use_sim_time` is fixed to true in all launches.

| argument | wheeled + legged (`fleet_bringup sim.launch.py`) | AUV (`fleet_auv auv.launch.py`) | drone (`fleet_drone drone.launch.py`) |
|---|---|---|---|
| `robot` | round (default), box, rover, truck, wyrm, hound, spider | fixed: knucker | fixed: wyvern |
| `world` | apartment, lab, warehouse, keep (default keep) | keep (default), tank, any world | lab (default), apartment, warehouse, keep |
| `namespace` | not available yet (G7) | knucker (ROS namespace; Gazebo model name stays knucker) | not available (PX4 topics are under /fmu) |
| `gui` | true | false | false |
| `rviz` | true | false | false |
| `camera` | false (D435) | false (forward camera) | not available |
| `nav`, `slam` | true, false | not available | not available |
| `spawn`, `x`, `y`, `yaw` | named spawn or pose override | not available | spawn (default takeoff), x, y, yaw |
| other | | `localization`, `controller`, `mission`, `cruise`, `log_csv`, `spawn_delay`, `exit_on_done` | `mission`, `mode`, `hover_alt`, `hover_time`, `mission_file`, `speed`, `accept_radius`, `shutdown_on_done`, `result_file`, `px4_dir`, `agent`, `xrce_port`, `fresh_params`, `spawn_delay`, `px4_delay`, `gz_ip`, `capture_dir`, `gnss_errors` |

Environment: `ROS_DOMAIN_ID` and `GZ_PARTITION` isolate parallel runs; `PX4_DIR` points at the PX4 checkout.

## Nav2, EKF and bridge parameter files

| file | role |
|---|---|
| `src/fleet_bringup/config/nav2_overrides.yaml` | deep-merged over the installed `nav2_bringup/params/nav2_params.yaml`; `sim.launch.py` then fills footprint, inflation, motion model and speed limits per robot kind and AMCL's initial pose from the world |
| `src/fleet_bringup/config/ekf.yaml` | robot_localization EKF (wheel/leg odometry + IMU yaw rate), `odom -> base_link` |
| `src/fleet_bringup/config/gz_bridge.yaml`, `gz_bridge_camera.yaml` | ros_gz_bridge topics; raw gz sensor topics are bridged under `/gz/` and re-published by the `fleet_sensor_sim` driver emulators with the real driver's topics |
| `src/fleet_bringup/config/bt/` | behaviour tree |
| `src/fleet_auv/config/ekf.yaml` | AUV EKF: DVL velocity, Bar30 depth, AHRS |
| `src/fleet_auv/config/tank_mission.yaml`, `tank.yaml` | tank mission and test setup |
| `src/fleet_drone/config/{missions,routes}/` | drone mission and route files for `mission_file:=` |

Ground Nav2/EKF values are tuned for the robots, not yet derived from sensor specs (G7).

## Where each number comes from

| quantity | source |
|---|---|
| sensor noise, rate, range, FOV, covariances | catalog entry `specs` (datasheet URL in the entry); IMU white noise = density x sqrt(rate) |
| motors, servos, batteries, thrusters, propellers | catalog entries (datasheets, vendor performance tables, fitted by `tools/fit_motor_prop.py` for the wyvern) |
| mass, CoM, inertia (ground) | `tools/mass_properties.py`: catalog part masses plus mesh statistics at the densities in `structure_materials.yaml` |
| AUV inertia, added mass, damping, buoyancy | S1 derivation in `src/fleet_auv/tools/derive.py` and `docs/notes/sea.md` (Fossen, Handbook of Marine Craft Hydrodynamics) |
| friction and contact | tyre catalog entry and world floor pairs, cited in `docs/notes/ground.md` (G2) |
| spawn poses, goals, drone waypoints | `worlds/<w>.yaml`, generated with the world |
| numbers marked `unpublished` or `estimate` | listed with the method in the entry; collected in the lane notes |

Known sources without a citation yet (honest list): legged joint velocity limits and `odom_scale`, rover and truck
`wheel_separation_multiplier`, wyvern base mass and inertia, Nav2/EKF tuning. See the README realism table.
